> **ChronosNet** — масштабная, высокоточная интерактивная среда визуализации и симуляции фундаментальных концепций компьютерных наук: распределенных систем, протоколов консенсуса, глобальной сетевой топологии BGP, парадоксов физического времени и киберустойчивости (DDoS).

Разработано в строгом инженерном стиле **Serenity System**: палитра темного графита (`#0a0b0e`, `#12131a`), акценты аметиста (`#7c3aed`) и неонового циана (`#38bdf8`), кастомная физика пакетов на HTML5 Canvas (60 FPS) и нулевая зависимость от внешнего бэкенда.

### 1. The Byzantine Consensus Sandbox (Парадокс византийских генералов)
* **Проблема:** Достижение консенсуса в асинхронной сети при наличии узлов, отправляющих противоречивые (эквивокационные) данные.
* **Математическая база:**
  * **PBFT (Castro & Liskov, 1999):** Гарантирует безопасность при условии $f < n/3$. Для $n = 5$ узлов максимальное число неисправных узлов $f = 1$, а размер кворума $2f + 1 = 3$.
  * **Raft (Ongaro & Ousterhout, 2014):** Модель Crash Fault-Tolerant (CFT) с выборами лидера, тайм-аутами сердечных сигналов (heartbeats) и репликацией журнала при кворуме $\lfloor n/2 \rfloor + 1$.
  * **Paxos (Leslie Lamport, 1998):** Фазы Propose / Promise и Accept / Accepted.
* **Интерактив:**
  * Мгновенная коррупция любого валидатора в состояние **Byzantine**.
  * Индукция сетевого раскола (**Split-Brain**) на изолированные партиции с визуализацией остановки прогресса в меньшинстве при нехватке кворума.
  * Инспекция реплицированного реестра (State Machine Ledger).

---

### 2. Global Topology & BGP Hijacking Simulator
* **Проблема:** Доверие между автономными системами (AS) в протоколе BGP-4 и уязвимость перед ложными анонсами префиксов.
* **Физика сети:** Глобальная карта магистральных оптоволоконных каналов с реальными задержками RTT (Ashburn, London, Frankfurt, Tokyo, Singapore, São Paulo).
* **Инструменты симуляции:**
  * **BGP Subprefix Hijack:** Внедрение фальшивого маршрута `/24` поверх легитимного агрегата `/16`. По правилу **Longest Prefix Matching (LPM)** трафик всего мира мгновенно перенаправляется на нелегитимную AS66666.
  * **RPKI ROA Validation:** Включение криптографической валидации происхождения маршрутов для отсечения вредоносных префиксов.
  * **Routing Loops & Severing:** Перерезание подводных кабелей в один клик с запуском алгоритмов перестроения путей **Dijkstra (SPF)** и **Bellman-Ford**.

---

### 3. Relativistic Clock Drift & Logical Timestamps (Проблема времени)
* **Проблема:** Кварцевые генераторы процессоров подвержены физическому дрейфу из-за температуры и напряжения ($\pm 10\dots 80$ PPM). В распределенных системах физическое время не может служить источником порядка событий.
* **Интерактив:**
  * Ползунки аппаратного дрейфа тактовой частоты (PPM).
  * Демонстрация **физического парадокса времени**: получение транзакции во времени, которое на целевом узле меньше времени отправки (нарушение причинности и двойные траты).
  * Разрешение конфликтов через **логические часы Лэмпорта** ($L(e') = \max(L(e), L_{msg}) + 1$) и **векторные часы** ($V_i$), математически разделяющие причинно-связанные события ($A \to B$) и параллельные гонки ($A \parallel B$).

---

### 4. DDoS Stress & Resilience Arena
* **Проблема:** Асимметричное исчерпание вычислительных ресурсов и очередей памяти целевого сервера.
* **Векторы атак:**
  * **SYN Flood:** Переполнение очереди неполных TCP-соединений (Half-open backlog).
  * **DNS Amplification:** Усиление трафика через уязвимые резолверы с коэффициентом $\times 64$ (запрос 64 байта $\to$ ответ DNSSEC 4096 байт).
  * **HTTP/2 Rapid Reset:** Массовая отправка и мгновенная отмена стримов.
* **Стек защиты:**
  * **Token Bucket:** Ограничение всплесков трафика (настраиваемая емкость и скорость пополнения).
  * **Anycast BGP:** Распыление объемного флуда по распределенным фильтрующим центрам очистки (Scrubbing PoP).
  * **SYN Cookies:** Бесстейтовая валидация рукопожатий без выделения памяти в ядре.
  * **Circuit Breaker:** Автоматический сброс нагрузки при критической загрузке процессора.

## 🚀 Быстрый запуск (Локально)

Проект собирается стандартными инструментами экосистемы Node.js:

```bash
# 1. Перейдите в каталог проекта
cd chronosnet

# 2. Установите зависимости
npm install

# 3. Запустите dev-сервер с горячей перезагрузкой
npm run dev

# 4. Сборка оптимизированного production-бандла
npm run build
```

Приложение откроется по адресу `http://localhost:3000`.

## 🌐 Деплой на GitHub Pages

Репозиторий полностью настроен для автоматической сборки и публикации в GitHub Pages без ручных настроек сервера.

### Инструкция по включению (1 минута):
1. Создайте новый репозиторий на GitHub с именем `chronosnet`.
2. Свяжите локальный репозиторий и отправьте код в ветку `main`:
   ```bash
   git remote add origin https://github.com/<ваш-username>/chronosnet.git
   git branch -M main
   git push -u origin main
   ```
3. Откройте в браузере репозиторий на GitHub:
   * Перейдите в **Settings** $\to$ **Pages**.
   * В разделе **Build and deployment** $\to$ **Source** выберите **GitHub Actions**.
4. GitHub Actions автоматически запустит готовый workflow `.github/workflows/deploy.yml`.
5. Через 40–60 секунд сайт будет доступен по публичной ссылке:
   ```
   https://<ваш-username>.github.io/chronosnet/
   ```

*Примечание:* Конфигурация `vite.config.ts` использует относительные пути `base: './'`, поэтому сборка гарантированно работает на любом имени репозитория или кастомном домене.
